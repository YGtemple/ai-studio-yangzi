# AI 影视本地知识桥

这是原有九个 AI 影视 Skill 外面的可选检索层。它只负责“找什么资料、为什么适合、哪些方法可以迁移”，不替代总控，不修改原有九个 Skill，也不创作剧本、图像提示词、表演或视频提示词。

## 什么时候使用

用户出现以下意图时启用：

- “结合本地知识库继续写。”
- “参考同类型电影节剧本，但不要抄剧情。”
- “先查编剧书，再修这一场。”
- “给当前剧本找最匹配的一个参考剧本。”
- 用户提交了已有大纲、剧本、角色卡、表演卡或镜头资料，但不知道应该参考哪部电影。

新项目第一次进入真正的创作任务时，如果项目里还没有记录知识库选择，允许主动显示一次 A/B/C 菜单，但显示菜单不等于调用知识库，也不得读取数据库正文。只有用户选择 B、C，或明确说“调用本地知识库、匹配本地参考、只查方法书”等同义口令后，才启用检索。用户选择 A 后原 9 Skill 完全照常工作。

## 首次配置与不同电脑

知识库不要求固定盘符，可以放在 Windows 任意磁盘、外接硬盘或 macOS 任意文件夹。推荐位置只是为了小白容易找到：

- Windows：`文档\AI STUDIO洋子AI电影工作流\本地知识库`
- macOS：`~/Documents/AI STUDIO洋子AI电影工作流/本地知识库`

所选根目录中必须包含 `99-索引与检索规则/curated-screenplay-methods.sqlite`；原始剧本与书籍可以继续保留其分类子目录。

用户第一次选择知识库B或知识库C时，如果尚未配置：

1. 只让用户选择一次知识库根目录，或直接选择 `curated-screenplay-methods.sqlite`。
2. Windows 运行 `scripts/configure_knowledge_base.ps1 -Root "用户选择的路径"`；macOS 或 Linux 运行 `python3 scripts/configure_knowledge_base.py "用户选择的路径"`。
3. 配置写入本 Skill 的 `references/knowledge-base.json`，该电脑上的所有电影项目共用，不要求每部电影重复配置。
4. 项目需要使用另一套知识库时，才允许用项目内 `00_project/knowledge-base.json` 覆盖全局配置。
5. 不要求学员手工编辑 JSON，也不能因为路径与作者电脑不同就回退到模型记忆。
6. SQLite 中如果保留了作者电脑的旧绝对路径，检索脚本会根据当前 `root` 和 `01-` 至 `99-` 分类目录自动重映射；必须同时报告原文是否能实际打开。

## 本期只处理影视创作资料

本 Skill 仍然只是第 10 个可选知识桥，本期只检索现有电影剧本、爆款短剧剧本、电影节资料和影视方法书，不扩展法律或其他专业知识库。每条本地结论必须带真实文件路径、页码或段落、短片段和实际查询词。没有命中就写“本地资料不足”，不得拿模型记忆或网络印象冒充本地结果。

## 首次主动提醒一次，选择后才调用

学员不需要懂电影，也不需要自己点名参考片。新项目在确认入口模式后、生成第一份创作成果前，如果 `00_project/reference-memory.md` 仍是“菜单未询问”，只显示一次：

> 【本地知识库，可选】A. 不调用，照原 9 Skill 流程；B. 智能匹配 3 至 5 部本地剧本和方法书；C. 只查本地方法书。选择前不会检索，请回复 A、B 或 C。

- 用户选 A：把菜单状态写为“已选择A-关闭”，立即回到原总控或原阶段 Skill；后续阶段不重复提示，也不检索。
- 用户选知识库B：模型自动提取题材、冲突、结构、人物关系、情绪、制作规模和文化背景，不要求用户提供电影名。
- 用户选知识库C：只检索编剧、导演、表演或电影技法书，不检索参考剧本。
- 用户直接说“不要参考”“直接继续”视为选择 A，并立即保存。
- 用户已经直接指定 B 或 C 时立即执行，不再重复显示菜单。
- 旧项目没有该状态时，在下一次相关创作任务开始前补问一次；已有 A、B、C 记录时不得重问。
- 用户可以随时用“这一步先查本地知识库”“新增一个本地参考”“替换参考方法001”主动开启新检索。
- 只有检索脚本成功返回真实本地路径、页码和命中查询词，才算调用本地知识库。专业模块中的创作执行规则不等于已经检索；没有来源证据时不得用模型记忆或网络常识冒充本地命中。
- 点名书名时可以先按文件名找到扫描版；如果结果显示“页码未提取”或“需要 OCR”，只能告诉用户文件已找到，不能把它当作已读内容交给创作 Skill。完成 OCR 或换成文字版并更新索引后才能使用书中方法。

## 用户确认参考后的定向精读

知识库 B 的第一轮只负责从全库找出 3 至 5 部候选，不代表模型已经读完这些书。用户确认参考后再执行第二轮定向精读：

1. 通常让用户确认 1 至 3 部；用户明确需要更多时最多 5 部。每部必须分配不同用途，例如结构、人物冲突、场面调度、表演或视听方法。
2. 第二轮画像写入候选卡中的完整路径到 `selected_documents`，并设置 `deep_read_selected: true`。不得只写模糊片名。
3. 为当前问题生成多组中英文查询。脚本会把检索范围硬限制在这些已确认文件，让所选书的全部已索引片段参与本地搜索，每个查询保留页码、片段号和原文证据。
4. “定向精读”不等于把几本书全文塞进模型。全文扫描和排序在本地 SQLite 完成，模型只读取本轮相关证据；这样比反复发送整本书更省 Token，也更不容易忘记。
5. 扫描版没有 OCR、正文没有进入索引或路径失效时必须停止并说明，不得假装已经精读。
6. 精读结论保存进项目 `reference-memory.md`。后续阶段需要细节时，继续限定这些已确认文件补查，不重新从全库随机匹配。

## 输入边界

1. 只读取用户本轮指定的当前项目文件或当前场景。
2. 不扫描其他电影项目，不读取旧聊天中的故事。
3. 不修改原项目文件；只新增 `00_project/knowledge-cards/` 下的知识卡和检索画像。
4. 视频反推、逐帧检查和素材识别不属于本 Skill。

## 检索画像

先从当前资料提取一张紧凑画像，保存为 `00_project/knowledge-cards/<阶段>-profile.json`：

- 当前阶段与本次要解决的问题；
- 是全库候选匹配，还是已确认参考定向精读；
- 定向精读时写入用户确认的完整文件路径；
- 题材、国家或文化背景、载体与目标时长；
- 主冲突、人物关系、主题、情绪和结构难点；
- 中文关键词与对应英文关键词；
- 需要的资料通道：参考剧本、编剧方法、文化事实；
- 禁止借用的具体人物、剧情链、独创设定和长段对白。

不要把整份剧本复制进画像。中文项目检索英文资料时必须生成英文查询词；只用中文查询会漏掉大量英文剧本。

## 三条资料通道

### 参考剧本

优先查询 `05-中日韩美高热类型片`、`06-全球电影节获奖剧本`、`07-用户授权完整剧本`，以及 `08-编剧方法书籍\\经典剧本范本`。

默认保留 5 部候选剧本。模型根据当前问题重新排序，通常选 1 部作为主参考；确有互补价值时最多组合 2 部。候选不是数据库总量，不能把“最终只选 1 部”解释成“本地只有 1 本”。

组合参考时必须分工，不得把几部电影的剧情拼接：

- A 片只参考结构或信息揭示；
- B 片只参考人物关系、冲突升级或表演策略；
- 必要时 C 片只参考氛围、类型承诺或视听方法；
- 每部都要列出“可以迁移的方法”和“禁止借用的具体内容”。

不得复制人物身份组合、核心诡计、完整事件链、标志性场面、独创世界规则或长段对白。相似度过高时必须提醒用户改换方法来源，而不是继续贴近原作。

### 编剧方法

优先查询 `08-编剧方法书籍\\编剧与影视专业书籍` 和 `08-编剧方法书籍\\开放版权经典`。

`影视研究期刊` 只在用户需要学术研究、电影史、作者研究或特定理论时查询；不得默认把 3,000 多份期刊混入普通创作。

`现代编剧经典-正版待导入` 只有实际导入正版内容后才能查询。

### 文化事实

只在神话、历史、制度、民俗、服饰、建筑和器物需要事实依据时查询 `01` 至 `04`。现代影视作品的原创设定不能冒充传统原典。

## 各阶段读取已确认参考的方法

- 菜单未选择或用户选择 A：所有阶段都不新增检索。
- 01 至 05：自动读取使用范围为“故事创作（01-05）”或“全流程”的启用方法。05 必须加载全部启用的故事方法。
- 06 Lira：只读取“图像资产（06）”或“全流程”的启用方法。
- 07 ACTING：只读取“表演（07）”或“全流程”的启用方法。
- 08 CINEDANCE：只读取“视频镜头（08）”或“全流程”的启用方法。
- 自动读取已有方法不等于重新检索。只有用户明确要求新增、替换或重新搜索时才查询数据库。

不得让所有阶段默认读取所有书籍，这会增加噪声并污染提示词。

## 执行

1. 先读取 `00_project/reference-memory.md` 的知识库菜单状态。状态为“菜单未询问”时，只显示一次 A/B/C 并停止；状态为 A 时立即返回原 9 Skill；只有 B、C 或用户新的明确检索口令才继续。首次使用若没有配置，先完成一次文件夹选择与配置。
2. 从当前资料自动生成双语检索画像，查询词应描述“当前要解决的创作问题”，不能只写宽泛题材名，也不能要求学员先提供电影名。
3. 运行 `scripts/retrieve_stage_sources.ps1`，对多组查询做全文检索、按文件去重和倒数排名融合。
   - 一至两个汉字的短词自动改用兼容检索，并按命中词数量与标题相关度排序。
   - 普通编剧方法检索默认排除 `影视研究期刊`；只有用户明确要求学术研究时才设 `include_journals: true`。
   - 可用 `path_excludes` 排除待精筛、广告合集或不适合本轮的目录。
   - 脚本默认先取 240 个相关片段再按文档去重，避免同一本书的多个段落占满候选位。
4. 读取候选结果，结合当前资料做一次模型复排，并为不同参考分配互不重叠的方法角色。
5. 把候选卡写入 `00_project/knowledge-cards/<阶段>-candidates.md`，在聊天中展示并让用户确认需要精读的 1 至 3 部参考。
6. 用户确认后生成第二张画像：写入 `selected_documents` 和 `deep_read_selected: true`，再运行同一脚本完成定向精读。
7. 把精读证据卡写入 `00_project/knowledge-cards/<阶段>-reference.md`，展示可迁移方法、页码证据和禁止借用内容，等待用户确认方法。
8. 用户确认方法后，不把整本书长期塞入上下文；把精简结论写入 `00_project/reference-memory.md`，分配编号，并标记使用范围、阶段适用图、预期落点与禁止借用内容。人物、关系与人物弧方法至少标记 02/05；世界规则、地点、阵营与物件方法至少标记 03/05；结构、场次、动作与对白方法按实际标记 01/04/05。故事类参考默认“故事创作（01-05）”。保存成功后才能继续创作。
9. 用户可以反复增加、采用、停用、恢复、删除或替换。每次先更新条目与“参考变更记录”；普通删除只停用留痕。
10. 继续调用原有总控或原阶段 Skill；当前阶段只读取使用范围匹配且启用的参考方法作为额外参考。

## 用户增加新剧本或工具书时

这叫“更新本地知识库”，不是重新训练大模型。用户把有权使用的 PDF、Word、Markdown 或 TXT 放进自己的知识库分类目录后：

1. 用户可直接说：`更新本地知识库：我刚加入了新的剧本和工具书，请只索引新增或修改的文件。`
2. Windows 运行 `scripts/update_knowledge_index.ps1`；macOS 或 Linux 运行 `bash scripts/update_knowledge_index.command`。
3. 只处理新增或修改过的文件，并保留未变化记录；不得每次重建整库。
4. 完成后报告扫描数、新增数、更新数、未变化数、失败数和报告路径。
5. 扫描版 PDF 无可提取文字时标为需要 OCR，不得声称已经可以检索。
6. 更新完成后，当前项目和以后新建的项目都可重新检索这些资料；不同电脑只需配置各自的知识库路径。

### 一句话自动整理

用户说 **“整理新剧本并更新知识库”** 时，读取 `references/inbox-workflow.md` 并完整执行。该口令是对“新加入待分类”入口内文件的本轮整理授权，不需要再逐个询问是否移动；但不授权删除、覆盖、修改正文、移动旧资料或操作知识库以外的文件。

系统必须读取该学员已经配置的实际知识库根目录，不得要求使用作者电脑路径。入口不存在就自动创建；入口为空就把完整路径显示在聊天中，让学员把网盘下载的文件放进去后重复同一句口令。入口有文件时，才执行安全解压、去重、分类和增量索引。

## 跨阶段延续与定向补查

- `reference-memory.md` 是跨阶段参考的唯一事实来源。新对话、新任务或上下文压缩后，先读取该文件即可恢复用户已经确认的参考方法。
- 进入 05 时必须加载所有启用的“故事创作（01-05）”方法。旧条目仍使用“适用阶段”字段时，故事方法即使只标了 `01`、`04`、`01/04` 或部分阶段，也自动迁移为该范围，不得静默过滤后重新搜索。
- 用户说“我喜欢某部作品的某个动作、场景、表演或镜头手法”时，先把它作为待确认意图，定向检索该来源的相关页码或片段；确认后才能新增参考方法。
- 需要更精确细节时，依据 `reference-memory.md` 中已确认的文件路径再次执行定向精读，通常返回 3 至 8 条本轮相关证据。不得依赖之前聊天里的模糊印象，也不得重新从全库随机换片。
- 第 05 阶段只把参考方法当作写作约束。最新已确认的大纲、角色、世界观和分场是剧本事实来源，优先级更高；已有启用方法时不得重复匹配新影片，除非用户明确要求。
- 02、03、05 不能只报告“已读取参考”。对应阶段成果必须另存 `00_project/reference-applications/<阶段>-<成果版本>.md`，写出方法编号、具体落点、未采用原因和冲突；没有落点就不能声称已经融合。

## 知识卡必须包含

- 本轮要解决的问题；
- 主参考剧本及匹配理由；
- 互补参考及各自只负责的方法维度；
- 可迁移的结构、场面或人物方法；
- 方法书来源与页码；
- 每部参考不得借用的具体内容与相似度风险；
- 本地文件路径、页码和实际查询词；
- 置信度与“资料不足”说明。

知识卡不能直接生成新剧情。原有九个 Skill 仍按原来的中文口令和调用方法执行。
