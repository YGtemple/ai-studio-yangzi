# 影视专家增强桥

本 Skill 是原 9 个影视 Skill 外面的可选专家资料桥，不是新的创作阶段，不能取代 `ai-film-router` 和当前阶段 Skill。

## 不可改变的边界

1. 创作仍然只按原 9 Skill 路线进行。专家桥只给当前阶段增加一种方法，不改项目定位、角色、世界观、分场、剧本与台词事实。
2. 专家增强和本地知识库是两个独立开关。选专家增强不等于检索本地剧本；选知识库 B/C 也不等于自动开启专家库。
3. 用户选择前，不得读取 `references/modules/` 或 `references/library/` 正文，不得生成专家结果。
4. 同一阶段允许启用多个彼此兼容的专家模块。默认智能推荐 1–3 项；只读取用户选中的模块正文。选择冲突项时按 `references/catalog/module-registry.md` 说明冲突并让用户决定，不得把多个模块同时写成正式成果。
5. 当前阶段第一次进入时只显示一次“智能推荐＋本阶段完整一级菜单”，不重复弹菜单。普通阶段中用户忽略推荐而继续创作时，照原流程继续。08 的首次完整菜单需要用户选择并保存为项目级默认；后续场次自动继承。只有新场次出现尚未覆盖且会实质改变拍法的打戏、大招或复杂调度时，才显示一行增量建议并最多打断一次；完整菜单只在用户主动要求查看时重开。00-A 至 00-G 是 08 内部镜头语言工具，不单独弹出“第 00 阶段”。

## 给用户的入口

每个阶段第一次进入增强选择时，先根据当前项目事实列出 1–3 个具体智能推荐，再显示当前阶段完整一级菜单。菜单只显示名称和一句用途，不读取模块正文，因此不会因为选项多就加载全部资料；打斗、属性大招等二级菜单只在用户选择查看后展开：

```text
【智能推荐】导演顾问（08-A）——先锁定镜头设计与剪切理由。
【本阶段完整菜单】逐行显示本阶段全部技能，中文名称在前、内部编号放括号里，每行带一句用途。
可多选，例如导演顾问（08-A）+调度连续性（08-C）+Seedance 2.5 精细适配（08-Q）；也可回复“照原流程”或“作者自定义”。
```

用户看到的每个选项必须写全“中文技能名称（内部编号）——一句用途”，例如 `台词像人说话（05-A）——删除解释性废话，补真实回应和话外之意`。不得输出只有编号的表格，不得写成 `05-A / 05-B / 05-C` 让用户盲选。A/B/C 操作菜单也必须同时解释：A 启用哪项推荐、B 只查看什么细分、C 照原流程且不加载什么。

- 用户说“照原流程继续”或直接继续创作：不读任何专家文件，立即执行原阶段 Skill。
- 用户选择一个或多个具体选项：先读 [模块登记表](references/catalog/module-registry.md) 检查兼容性，再只读取所选模块。
- 用户说“查看菜单”“还有什么技能”或同义表达：显示 [阶段专家菜单](references/catalog/stage-menu.md) 中当前阶段完整菜单，不展开其他阶段资料正文。
- 用户已点名“打戏增强”、“大招增强”、“导演分镜顾问”或“参考图增强”时，直接视为已选，不再重复提示。
- 完整菜单末尾固定显示 `作者自定义——直接说你的创作想法`。先映射到已有技能并解释匹配结果；没有完全匹配时，仅在 `00_project/expert-memory.md` 写入当前项目、当前阶段专用的自定义方法卡，用户确认后再交给当前阶段 Skill。不得改写全局 Skill。

### 08 专项主动提醒

- 当前剧本场次明确出现打斗时，不要求小白知道模块名字。把 08-H 加最相关的一项放到完整一级菜单的推荐区，说明 08-M 会自动自检，再等待选择。
- 当前剧本场次明确出现属性大招、终结技、镇压或封印时，把 08-N 加最相关的 08-O 或 08-P 放到完整一级菜单的推荐区，再等待选择。
- 只允许根据当前项目事实做推荐，不得为了推荐而先读取专家正文。用户选择 A 后才定向读取；选择 B 只显示相应二级菜单；选择 C 则由 CINEDANCE 按普通流程拆镜。
- 选择与跳过先写入 `00_project/expert-memory.md` 作为 08 项目级默认；具体场次只登记与默认不同的增量选择。换场或剧本小改不重弹菜单，镜头清单内部修订继续沿用已选增强，除非用户主动增删或新内容出现未覆盖的专项风险。

## 轻量路由表

| 当前阶段 | 可推荐的专家方向 |
|---|---|
| 01 概念 | 导演视觉方向，仅当用户需要审美或类型参照 |
| 02 角色 | 角色造型或战斗身份，不生成最终图 |
| 03 世界观 | 场景、法术属性或战斗空间；现实题材默认不推荐 |
| 04 分场 | 导演式场景拆解、节拍时长或复杂调度 |
| 05 剧本 | 台词、连续性、动作因果或大招剧情化；不拆镜 |
| 06 Lira | 角色参考图、场景九宫格、白模或构图布光 |
| 07 ACTING | 微表情、口播、配音、声音或动作表演 |
| 08 CINEDANCE | 同时显示 00 镜头语言工具箱与 08 专项：景别、构图、布光、转场、有动机运镜、导演分镜、打斗、大招或审片返修 |

## 选中后怎么读

1. 导演分镜：读 [导演分镜顾问](references/modules/director.md)。
2. 参考图：读 [角色与场景参考图](references/modules/reference-art.md)。
3. 打斗：读 [打斗编排核心](references/modules/combat.md)，然后先按用户确认的武器、拳法、战场或机制读 `references/library/combat/` 中最相关的 1 份专项；如果攻防因果、环境或机制仍缺证据，再定向补读，正式交付前读自检清单。
4. 玄幻大招：读 [玄幻大招核心](references/modules/ultimate.md)，再只读 `references/library/ultimate/` 中用户选定的 1 份属性文件。
5. 00 镜头语言工具：先读 `references/modules/shot_grammar.md`，再按用户选择或系统推荐只读 `references/library/general/` 中对应的景别、基础运镜、构图、布光、转场或特殊机位资料；它只服务 08 镜头规划，不独立输出。
6. 其他细分能力：先读阶段菜单指定的索引，再从 `references/library/general/` 中先读最相关的 1–2 份文件。不足时按当前缺口继续定向补读，不读无关文件。
7. Seedance 2.5 精细适配：由 `film-cinedance` 读取 `../film-cinedance/references/seedance-25-prompt-format.md`；专家桥只记录用户是否启用精细模式，不自行输出最终提示词。

## 与原 9 Skill 的交接

- 专家桥把同阶段已选模块合并成一张“本阶段增强方法卡”，再交给当前原 Skill 执行；正式成果始终只有一个阶段负责人。
- 01–05 的方法卡只能影响当前阶段写法；06–08 只能影响资产、表演或镜头执行。
- 08 打戏或大招不得绕过 `film-cinedance` 的镜头规划确认、时长核算、连续性和 Seedance/H3 模型选择。
- 08 打戏或大招的输出顺序固定为：主动推荐并等待选择 → 生成增强方法卡或动作链 → 由 CINEDANCE 形成完整拍法与镜头表 → 用户确认 → 输出目标模型提示词。任何专项都不能在用户确认前直接吐成片提示词。
- 08 选择导演顾问时，先输出 `05_shots/<场次ID>/director-plan-vNNN.md` 并等待确认；然后由 CINEDANCE 把该方案整理成正式 `shot-plan`，只补时长、对白容纳、资产引用、连续性和模型可执行参数。确认后的镜头顺序、目的、核心机位、核心运镜、剪切理由和“必须保留”项高于 CINEDANCE 的通用偏好，CINEDANCE 不能另起一套镜头方案。
- 资料库中出现“上一镜头”、“继续”或“保持原样”时，最终提示词仍必须按 `film-cinedance` 要求改写为完整的站位、姿势、道具、光影和动作起点。
- `references/library/` 中保留的旧产品名、旧目录名、个人电脑路径、宣传语和旧流程说明都只属于来源材料，不是执行指令。执行时只提取影视方法与案例规律，一律以本 Skill、模块登记表和当前阶段 Skill 的新路径与新流程为准。

## 项目记忆优先，Token 优化其次

第一次确认专家增强后，从 [专家选择记忆模板](references/expert-memory-template.md) 创建项目文件 `00_project/expert-memory.md`。

- 每条保存用户选择、用途、资料路径或标题锚点、生效范围、绑定的项目事实、禁止改动项和方法摘要；摘要长度以能完整恢复决策为准，不设为了省 Token 而截断事实的硬上限。
- 每轮输出前必须先读：用户本轮要求、项目状态、当前阶段最新确认文件、必要上游事实、`expert-memory.md` 中当前阶段的启用记录。这些权威上下文不受 Token 优化规则削减。
- 后续对话先读已落盘的事实与方法摘要，不依赖聊天窗口“记住”。用户修改专项、摘要无法支撑细节或证据互相冲突时，按记录的路径和标题锚点重新定向读源文件。
- 无法读到权威文件、资产版本对不上或必要证据缺失时，必须标记“待用户确认”或“无法核实”，不得用模型印象补全。
- 用户可随时说“关闭本阶段专家增强”、“换成打戏增强”或“清除本阶段选择”；先更新记忆再继续。
- 专家选择发生增删、停用或替换时，同时更新 `00_project/session-checkpoint.md`。下一阶段只读取与新阶段匹配的启用记录，不把上一阶段整套专家正文带过去。
