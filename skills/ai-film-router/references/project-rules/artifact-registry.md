## 固定状态

- `草稿待确认`：已经写入本地，但不能交给下一步骤。
- `已确认-当前`：当前唯一允许继续往下走的版本。
- `历史已替代`：曾经确认过，保留查阅，不再默认使用。
- `已过期-禁止使用`：依赖的上游已经改变，不得继续生成或交付。
- `缺文件-阻断`：登记路径不存在或不可读，必须先修复。

## 维护规则

1. 每次形成可供用户检查的完整成果，先写入新的 Markdown 版本并确认文件存在，再登记为“当前草稿”和展示；修改不得覆盖旧版本。
2. 用户确认前，旧的最新确认稿仍有效；新草稿不得进入下一步骤。用户明确确认后，新草稿才升级为“最新已确认”。
3. 同一阶段恢复工作时读取“当前草稿＋最新已确认”；跨阶段只能读取“最新已确认”。
4. 新版本确认后，旧确认稿变为“历史已替代”；依赖旧确认稿的下游立即变为“已过期-禁止使用”，不能继续作为默认输入。
5. 01 至 05 可以按整阶段登记；06 按角色/场景/状态 ID，07 按场次 ID，08 必须按场次建立 `05_shots/<场次ID>/scene-registry.md`，避免修改一处使全项目重跑。
6. 08 的导演方案、时长、镜头清单、空间图、连续性、分镜图绑定、视觉质检、关键帧和各模型提示词分别登记。提示词必须写明依据的镜头清单、空间图、连续性、实际参考图、视觉质检、关键帧、资产、ACTING 和目标模型版本。
7. 新镜头清单确认后，依赖旧清单的提示词包立即“已过期-禁止使用”。新提示词包只重编受影响镜头，未改镜头从上一包继承并写明来源。
8. 用户给的是已有标准剧本时，先把原文件登记为“作者锁定原剧本”，再生成生产拆解；不得把原稿与 05 生成剧本混为同一成果。
9. 版本统一使用三位数 `v001`。生成新版本前扫描同目录已有文件取最大编号加一，不得靠聊天猜编号。
10. 写文件采用“临时文件写完后替换”的方式；文件成功后再更新登记。任一步失败都保留旧确认稿并立即说明。
11. 同一项目同一时间只允许一个 Agent 写入。能运行 Python 时先调用 `artifact_guard.py acquire-lock`，完成后释放；检测到其他 Agent 的锁时停止写入。
12. 旧项目升级时保留旧登记表备份，再建立 V3.3 登记；旧记录未迁移完成前不得假装版本已经确认。
13. 02、03、05 加载本地参考方法时，必须登记对应 `reference-applications` 应用单；应用单没有具体落点时不能把参考标记为已采用。
14. 每个正式视频镜头必须登记实际可读的本镜参考图。换图会使该镜及受影响连续区间的旧质检和提示词过期，但不无差别作废整场。
15. 04 时长是写作预算；05 每份完整剧本草稿必须登记成稿时长复核。08 不得直接照抄 04 数字，必须结合 05 成稿、07 ACTING 和当前镜头重新核算。
