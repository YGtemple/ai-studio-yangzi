## 规则

- 一次只执行一个专业 Skill。
- 允许从任意阶段开始，也允许主动切回上游修订。
- 项目事实以登记状态为“已确认-当前”的阶段 Markdown 为准；`session-checkpoint.md` 只保存当前阶段的中途进度和未决问题。
- 每个阶段的当前草稿、最新确认稿、依据版本和过期下游统一登记在 `artifact-registry.md` 与 `artifact-state.json`；不得靠聊天记忆猜版本。同阶段恢复读取当前草稿与最新确认，跨阶段只读最新确认。
- 不按模型上下文长度猜测何时保存。遇到重要决定、长草稿、阶段切换或上下文压缩时自动保存；保存失败必须提示用户。
- 未经用户明确要求和确认，不改掉其他阶段已确定内容；切换和修订必须记录版本及影响范围。
- 模板不包含任何示例故事、角色、剧本或资产。
- 参考方法不得覆盖最新已确认的项目事实；只记录用户确认过的参考方法编号。
- 已有标准剧本默认锁定原文；补角色、场次、资产、表演和镜头资料不等于改写剧本。
- 已有标准剧本的时长初估来自作者剧本接管，不要求重跑 04；08 再按最终对白与表演重新核算。
- 从零项目的 04 时长只是写作预算；05 成稿后按准确对白和动作复核，07 加表演停顿，08 才形成最终镜头时长。
- 08 阶段先确认 `05_shots/` 镜头规划与空间图，再绑定每镜实际分镜图并完成视觉连续性质检，最后输出 `06_prompts/`；每条提示词同时引用本镜图片并独立写全连续性状态。
- 镜头清单生成新确认版本后，依赖旧镜头清单的视频提示词立即标记为“已过期-禁止使用”；新提示词按场次与模型分别保存、分别确认。
