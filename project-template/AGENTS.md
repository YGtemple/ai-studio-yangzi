# AI 影视项目弹性总控

本项目配套 `ai-film-router`。用户提出影视创作请求时，先读取当前用户 Skill 目录中的 `ai-film-router/SKILL.md`。

1. 新项目第一轮先判断入口：A 从零创作；B 已有完整标准剧本；C 已有部分资料；D 高手镜头优化。入口不清楚时只问这一次，记录后不重复。
2. 一次只调用一个专业 Skill，但允许用户主动切换到任意阶段。
3. 没有用户明确要求和确认，不改掉其他阶段已经确定的内容；用户要求修改上游时，留版本、切回该阶段并标记受影响下游。
4. 用户已有剧本、角色卡、资产图或表演文件时，只登记他明确指定的权威输入，不强迫重跑无关前序。完整标准剧本先做接管检查：报告缺少的角色状态表、场次制片表、时长预算、资产表、表演节拍或镜头连续性资料；确认后由总控生成包含逐场时长初估和下一步路线的生产拆解，不要求重跑 04，未经授权不得改写作者剧本。
5. 用户可以直接说“只做 CINEDANCE”“从 Lira 开始”“回到剧本阶段修改第8场”。
6. 项目模板和空目录中不得写入示例故事、角色、资产或旧项目内容。
7. 每个阶段的完整结果必须同时显示在聊天窗口并保存到项目 Markdown 文件，不能只回复文件路径。
8. 用户在聊天中修订后，先写入新的 Markdown 版本并更新 `artifact-registry.md` 与 `artifact-state.json`；旧版本保留。同阶段恢复读取当前草稿与最新确认，下一阶段只读取状态为“已确认-当前”的版本。
9. 每个阶段开始前读取 `00_project/project-status.md`、`00_project/routing.md`、`00_project/artifact-registry.md`、`00_project/artifact-state.json`、`00_project/session-checkpoint.md` 和 `00_project/reference-memory.md`，只加载状态为“启用”且适用当前阶段的参考编号；用户最新确认的项目文件始终优先。02、03、05 使用参考方法时必须同时生成阶段应用单，写清具体落点，不能把“已读取”冒充“已融合”。
10. 进入 Lira 前必须已有可供生产使用的角色状态、场景与道具资料；缺少时先从作者剧本提取为独立生产资料，不把剧本改成提示词。
10.1 从零项目的 04 时长只是写作预算。05 每次完整剧本草稿必须生成成稿时长复核；硬时长超限在确认 05 前处理，07 加入演员停顿与反应，08 才做最终镜头核算。
11. 08 阶段内部固定为四步：镜头与时长规划；场景空间图与连续性；逐镜绑定实际分镜图并做视觉质检；最后为已确认版本生成 Seedance 2.5、Seedance 2.0、MiniMax H3 或多版本提示词。所有文件按场次保存，仍是原第 08 阶段。
12. 每条正式视频提示词必须绑定本镜实际分镜图并独立写全起始状态，不得使用“上一镜头、继续、同上、保持原样”等关系词。同机位可用前镜尾帧；换角度或焦段必须使用本镜新机位图，同时继承真实站位、动作、光影、道具、伤势和对白状态。
13. 第一次进入 08 时显示一次完整专家菜单并保存项目级默认。后续场次自动继承；只有出现新的打戏、大招或复杂调度风险时才显示一行增量建议，完整菜单不因换场反复出现。
14. 用户确认、否定或修改重要事实，系统生成较长草稿，准备切换 Skill，或平台提示上下文压缩时，后台更新 `00_project/session-checkpoint.md`。成功后只在回复末尾报告一次保存路径，不反复询问；写入失败必须立即说明，不能假装已经保存。
15. 检查点中的“未确认想法”不得当成正式事实。切换 Skill 时先保存检查点，再只把最新已确认文件、必要上游事实和当前阶段启用方法写入新路由；上一阶段的无关方法与候选内容不得继续携带。
16. 每次完整成果和每次修改都生成三位版本号的新版本。新镜头清单确认后，依赖旧清单的视频提示词标记为“已过期-禁止使用”；回到提示词步骤时只读取最新确认镜头清单，新提示词包只重编受影响镜头并继承未改镜头。
17. 06 按资产 ID、07 按场次 ID、08 按场次与模型登记影响范围。空间图、分镜图绑定、视觉质检和关键帧都必须登记版本；镜头、图片或连续性改变后不得继续使用受影响的旧提示词。
18. 同一项目同一时间只允许一个 Agent 写入；检测到其他 Agent 的项目写入锁时停止修改。文件写入成功后才能更新登记表。

## 可选专家增强

1. `film-expert-bridge` 只增强当前阶段，不取代原专业 Skill。
2. 每个阶段第一次进入增强选择时先显示最匹配的 1–3 项，再显示当前阶段完整一级菜单。用户可多选；选择前不加载模块正文，专项二级菜单只在用户选择查看时展开。08 的选择保存为项目级默认，后续场次不重复整套菜单。
   每个选项必须同时显示“中文技能名称（内部编号）——一句用途”，例如 `台词像人说话（05-A）——删除解释性废话并补真实回应`；禁止只显示 `05-A` 或只显示 A/B/C 字母。
3. 用户不选时照原流程继续，同阶段不重复提示。
4. 用户选定前不读专家正文。选定后先定向读 1–2 份最相关资料，证据不足时继续补读，不得猜测。
5. 首次启用时创建 `00_project/expert-memory.md`。每轮先读项目最新文件和该记忆，不依赖长对话记忆。
6. 完整菜单末尾显示“作者自定义”。先匹配已有技能；没有完全匹配时只建立当前项目、当前阶段专用的方法卡并等待确认，不得修改全局 Skill。

## 可选本地知识桥

本项目同时支持 `film-knowledge-bridge`，但它不是创作阶段，也不改变原 01 至 08 的路由。

1. 新项目确认入口模式后、首份创作成果前，若项目仍是“菜单未询问”，主动显示一次知识库 A/B/C；显示菜单不检索。
2. A 表示关闭并照原流程，B 表示智能匹配 3 至 5 部剧本和方法书，C 表示只查方法书。保存选择；B/C 才检索，同一项目不重复询问。
3. 学员不需要提供电影名。知识桥自动提取题材、结构、冲突、人物关系、情绪、制作规模和文化背景。
4. 多部参考必须分工，只迁移结构、人物方法、氛围或视听技巧；不得拼接剧情、复制核心诡计、人物组合、标志性场面或对白。
5. 知识卡先在聊天中完整展示并等待确认；只有确认后的知识卡才能作为当前专业 Skill 的附加参考。只有真实本地路径、页码和命中词齐全时才算本地命中。

## 跨阶段参考记忆

1. 候选知识卡不自动进入后续阶段。用户明确确认采用后，才写入 `00_project/reference-memory.md` 并分配参考方法编号。
2. 条目必须记录来源、本地路径、页码与命中词、允许迁移的方法、使用范围、绑定的项目事实和禁止借用内容。故事类方法默认“故事创作（01-05）”。
3. 进入新阶段时，先读取完整参考记忆，再自动加载使用范围包含当前任务的启用条目；只用一句话报告编号，不重新检索。
4. 用户可反复增加、采用、停用、恢复、删除或替换参考；每次先实时写入文件。普通删除只停用留痕。
5. 用户指定喜欢某部作品的某个动作、场景或手法时，先定向检索该来源并等待确认，再写入新条目；不得把用户说的片名直接当作已经核实的本地来源。
6. 第 05 阶段必须以最新已确认的概念锚定、角色、世界观和分场为主，再使用适用的参考方法。任何参考与项目事实冲突时必须停下询问，不能静默改写。
7. 02、03、05 输出时，参考方法必须另存阶段应用单，逐条写明人物、关系、世界规则、场次、动作或对白的实际落点；没有落点不能声称已融合。

## 01 与 05 强制检查

- 从零进入 01 时，第一条创作回复必须逐字显示 `film-synopsis/references/source.md` 的洋子项目定位 A/B/C/D 菜单并停止，不得替换成其他问卷。
- 进入 05 时，自动迁移旧项目“适用阶段”字段中属于故事方法、只标了 `01`、`04`、`01/04` 或部分阶段的条目为“故事创作（01-05）”，并加载所有启用的故事参考；不得因为标签遗漏重新搜索目录。

如果本机尚未安装 `ai-film-router`，提示用户先完成课程包安装，不自行虚构路由规则。
